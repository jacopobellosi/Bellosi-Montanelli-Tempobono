\section{Implementation, Integration and Test Plan}

The implementation of the Best Bike Paths (BBP) system follows a structured, dependency-driven approach, aligning with the Client-Server architecture defined in Section 2. The development process is divided into \textbf{Backend} and \textbf{Mobile} streams, which proceed in parallel where possible and merge at critical integration points.

Deployment and testing environments will leverage \textbf{Docker} containerization from the very first step to ensure consistency between development, testing, and production environments.

\subsection{Dev-Step 1: Core Infrastructure (Auth \& Data)}
\textbf{Goal:} Establish the persistence layer and user identity management.
\begin{itemize}
    \item \textbf{Backend Implementation:}
    \begin{itemize}
        \item Setup of the \texttt{PostgreSQL} container with the \texttt{PostGIS} extension enabled.
        \item Implementation of the \textbf{Model} component (Repository pattern) and the \texttt{User Service}.
        \item Development of the \textbf{Auth Service} implementing the \texttt{authentication interface} and \texttt{token creation interface}.
        \item Configuration of the \textbf{Security Module} (Middleware) to validate JWTs.
    \end{itemize}
    \item \textbf{Mobile Implementation:}
    \begin{itemize}
        \item Setup of the project structure and \textbf{Local Storage} (e.g., SQLite/SharedPreferences).
        \item Implementation of the \textbf{Network Layer} to consume the REST API.
        \item Implementation of Login/Register screens in the \textbf{UI Layer}.
    \end{itemize}
    \item \textbf{Integration Test (I1):} Verify that the Mobile App can successfully register a user and receive a valid JWT token from the Dockerized Backend.
\end{itemize}

\subsection{Dev-Step 2: Path Management (Geospatial Core)}
\textbf{Goal:} Enable the creation and retrieval of Path entities.
\begin{itemize}
    \item \textbf{Backend Implementation:}
    \begin{itemize}
        \item Implementation of the \textbf{Path Service} (specifically \texttt{Path Adding} and \texttt{Path Searcher}).
        \item Implementation of geospatial queries (\texttt{findPathsByLocation}) in the Model using PostGIS functions.
    \end{itemize}
    \item \textbf{Mobile Implementation:}
    \begin{itemize}
        \item Implementation of the interactive Map component.
        \item Development of the "Create Path Manually" flow (UC11), caching draft paths in \textbf{Local Storage}.
    \end{itemize}
    \item \textbf{Integration Test (I2):} Verify that a path geometry drawn on the mobile device is correctly serialized (GeoJSON), sent to the backend, and stored as a PostGIS geometry.
\end{itemize}

\subsection{Dev-Step 3: Mobile Sensor \& Recording Logic}
\textbf{Goal:} Develop the client-side hardware abstraction. (Independent of Backend).
\begin{itemize}
    \item \textbf{Mobile Implementation:}
    \begin{itemize}
        \item Implementation of the \textbf{Sensor Manager} to abstract GPS and IMU streams via the \texttt{Sensor interface}.
        \item Development of the \textbf{Recording Service} to manage the \texttt{GPS Tracker} and \texttt{Stats Tracker}.
        \item Implementation of the \textbf{Sensor Processor} algorithm to detect potholes (R24) and log events via the \texttt{Processing sensor interface}.
    \end{itemize}
    \item \textbf{Unit Test (T3):} Field testing with physical devices to calibrate accelerometer thresholds for the \texttt{sensor\_event} generation.
\end{itemize}

\subsection{Dev-Step 4: Trip Integration \& Persistence}
\textbf{Goal:} Connect recorded data to the backend persistence.
\begin{itemize}
    \item \textbf{Backend Implementation:}
    \begin{itemize}
        \item Implementation of the \textbf{Trip Service} (\texttt{Trip Adding}, \texttt{Trip Searcher}).
        \item Integration of the \textbf{Weather API Client} to fetch snapshots via the \texttt{Weather interface}.
        \item Implementation of the Transaction Script in the \textbf{Controller} to atomically save Trips, Paths, and Reports.
    \end{itemize}
    \item \textbf{Mobile Implementation:}
    \begin{itemize}
        \item Implementation of the "Save Trip" workflow (UC9), linking the \textbf{Recording Service} output to the \textbf{Network Layer}.
        \item Implementation of the \textbf{Review Detections} screen (UC8).
    \end{itemize}
    \item \textbf{System Test (S1):} End-to-end verification: \textit{Record $\rightarrow$ Stop $\rightarrow$ Review $\rightarrow$ Save $\rightarrow$ Verify Data in DB}.
\end{itemize}

\subsection{Dev-Step 5: Advanced Features}
\textbf{Goal:} Complete the ecosystem with navigation and scoring logic.
\begin{itemize}
    \item \textbf{Mobile Implementation:}
    \begin{itemize}
        \item Implementation of the \textbf{Navigation Manager} to trigger external apps via OS Intents (UC6).
    \end{itemize}
    \item \textbf{Backend Implementation:}
    \begin{itemize}
        \item Implementation of the \textbf{Path Merger} to calculate fresh status on read.
        \item Enabling the \textbf{Trip Service} to trigger path scoring updates when a public trip is saved.
    \end{itemize}
\end{itemize}

\subsection{Dev-Step 6: Release \& Deployment}
\begin{itemize}
    \item \textbf{Containerization:} Finalizing \texttt{Dockerfile} configurations for the Backend Server and Nginx Load Balancer.
    \item \textbf{Deployment:} Deploying the container cluster to the production environment.
    \item \textbf{Beta Testing:} Releasing the Mobile App to a limited user base to stress-test the system under concurrent load.
\end{itemize}
